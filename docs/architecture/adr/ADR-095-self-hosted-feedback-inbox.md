# ADR-095：自建反馈收件与显式提交

- 状态：接受（M4-63项目切片）
- 日期：2026-11-05
- 需求：F31 / E74

## 决策

问题反馈/功能建议只通过用户在设置中配置的自建服务根地址提交。默认未配置，入口禁用且应用保持离线。用户填写类别、描述（1–2,000字符）及可选联系方式后，必须先看到接收根地址和完整字段预览，再点“确认发送”。不附加应用版本、设备、操作系统、浏览器、棋谱或诊断数据。公网只允许HTTPS；HTTP仅限loopback开发地址。

客户端经`FeedbackService`端口POST `/v1/feedback`，限制字段/schema/超时/响应大小；服务地址及消息使用类型化失败。提交接受响应不能证明运营者已阅读或回复。失败时明确区分HTTP拒绝、无效确认和连接/超时的不确定送达，不自动重试，避免重复提交。

服务端路由仅在设置`CHESSNEXT_FEEDBACK_ROOT`时启用。请求为schema 1，只接受`kind`、`message`及可选`contact`，总请求上限16KiB；未知字段（尤其遥测/棋谱）拒绝。内容用随机文件名独占写入已有私有目录，最多5,000条；Dart服务不记录请求IP或提交内容，无公开读取、列举、删除或邮件转发接口。传输连接会让服务/托管层看到来源IP等网络信息；Nginx样例为该location关闭access log，但运营者仍需管理错误日志。部署者需提前创建0700目录、仅授予服务账号写权限，并制定本地审阅与删除流程/保留期限。随仓库Nginx样例限制每IP每分钟6次、突发5次。默认服务配置不启用此路由。

## 边界与未完成

此片只覆盖问题反馈/建议。附件上传、版权投诉（含权属真实性声明及附件）、外部邮箱/讨论群入口、邮件通知、运营者部署实例和实际保留策略仍未实现/验收。真实参考站接收地址和数据保留仍U。F31保持开放；不能声称反馈服务端到端已经在生产运行。

## 验收

- 客户端loopback协议测试确认仅发送用户填写字段；公网HTTP在发网前拒绝。
- UI测试确认预览阶段零请求，明确确认后才提交；空描述不发送。
- 服务端测试确认严格字段、长度边界、私有存储及无公开读取路由。
- 确认文案说明网络连接会向服务/托管层暴露来源IP等连接信息。
- 根目录串行测试、analyze、macOS既有实例热重启及服务端专项记录于TRACEABILITY。
