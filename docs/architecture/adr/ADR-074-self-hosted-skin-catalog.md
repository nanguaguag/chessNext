# ADR-074：自建可替换棋子皮肤目录

- 状态：已接受（服务端首片）；Flutter目录接入待后续实现
- 日期：2026-11-04
- 需求：F21、B24；参考证据：E42

## 背景与范围

E42观察到访客可见在线皮肤目录、作者/名称/点赞计数、默认/点赞最多/名称/作者/最新导入排序、显式提交搜索，以及ZIP/图片/文件夹导入入口。没有验证点赞写入、用户上传、在线条目下载/应用成功、公开目录API或登录门槛。用户要求在线能力保留在总范围，后端由用户自建且可替换；登录后能力不实现。

本片只交付公开只读HTTP目录服务和部署方案，不接入Flutter UI，不声称在线目录功能已经对齐。它不访问或复制参考站数据/资源，不实现账号、上传、点赞写入、评论、推荐或遥测。目录运营者离线维护元数据和项目skin ZIP；likes字段是运营者提供的排序值，不是实时用户投票。

## 服务契约

- `GET /healthz`
- `GET /v1/catalog?q=&sort=default|likes|name|author|recent&page=1&pageSize=24`
- `GET /v1/catalog/{id}`
- `GET /v1/catalog/{id}/package`
- 目录数据为schema1 JSON；下载包使用现有项目单皮肤ZIP schema1。每项要求名称、作者、描述、发布日期、许可证、署名、静态likes和包SHA-256。
- 只读服务只允许GET/HEAD与CORS预检。查询、分页、清单和包体有界；ID严格白名单，包只从固定`packages/<id>.zip`路径读取，拒绝符号链接并在发送前校验声明SHA。不可变内容按SHA返回ETag。
- 目录在进程启动时加载；运营者先准备完整新版本，再原子切换目录并重启服务。应用侧后续经可替换的`PieceSkinCatalog`端口访问，不让UI直接处理HTTP或服务器JSON。

## 部署方案

使用Linux小型VM或自管容器宿主机。构建并发布`dart compile exe`生成的单一服务二进制，以无登录交互的非root系统用户运行，监听`127.0.0.1:8087`；将元数据和packages放在单独只读发布目录。Caddy或Nginx终止TLS并反代，设置并发/请求速率限制、最大响应和访问日志轮转。进程只需读取发布目录；发布流程校验license/attribution与包hash后原子切换目录并重启。备份目录和清单，滚动回退上一个已校验版本。服务自身没有管理写接口。

初始开发数据为空，仓库不捆绑未授权的示例皮肤。运营者必须只发布自有或有再分发权的原创包，并提供可核验许可/署名。远程URL偏好、下载缓存、断网行为和实际macOS/其它平台客户端仍是后续F21工作。

## 验收和未覆盖

服务测试覆盖默认人工顺序、点赞/名称/作者/最近排序、搜索/分页、许可信息、hash校验、ETag、无效查询、拒绝写方法及损坏包。服务成功不代表Flutter客户端已接入、用户可在UI选择服务器地址或在线目录完整对齐。用户评分写入与上传仍待后续审计；因登录范围排除，本ADR不引入账号方案。
