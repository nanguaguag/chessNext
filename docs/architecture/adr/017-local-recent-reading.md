# ADR-017：独立本地阅读位置与安全恢复

2026-11-02，F18/B06,B19。E17仅验证参考访客最近阅读入口和空态；公开只读页未成功加载着法、未验证记录生成，不能推断网站存储/恢复算法。本增量为明确离线设计，验收见TRACEABILITY。

## 数据与所有权

RecentReadingRepository只保存最多50条本机元数据（ID、标题、根FEN、根到游标着法路径、阅读时间），不存第二份棋谱。RecentReadingController监听库/会话，绑定LibraryController.documentEpoch；保存/打开成功后才能记录，未保存新局/导入副本不入历史。旧库ID不能因刷新重新绑定外部替换的新文档；保存也仅在绑定epoch匹配时沿用ID，避免覆盖旧谱。

每次实际读谱位置变化去重前置，打开也刷新阅读时间；选子、引擎info和同位置注释不刷时间。按事件顺序排列，不依赖系统时钟单调性；时间用于显示。300ms合并/串行写入，后台和正常退出flush。初始化慢读取与本轮事件合并，本轮优先；未加载成功禁止自动覆盖，重试后才继续持久化。

## 恢复

点击最近阅读加载最新保存棋谱，经根FEN+整条着法路径匹配后恢复，禁止只信节点ID。缺失路径或换根保留棋谱保存时默认位置并明确提示，未保存新分支由独立草稿负责。未来线路锚点沿用保存的GameTree导航规则，不额外承诺保存所有未来分支选择。普通棋谱库打开沿用保存位置；最近阅读入口才使用阅读标记。

UI确认替换dirty后再次核验epoch/revision/positionRevision；LibraryController原有IO晚到校验保留。实际内容替换触发引擎旧epoch失效。阅读列表本身不走棋/不启动AI、不修改棋谱modifiedAt/内容dirty；丢失记录不自动删历史，错误可见。

## 存储与失败

正式main注入ApplicationSupport/chessnext-reading schema1 JSON，2MiB/50条/1999着路径上限；顺序保存、去重ID校验、格式/坐标/日期/rootFEN验证。串行暂存flush后同目录rename，保留有效备份，坏主文件恢复后首次写入另存原件。两份坏则保留文件并禁止自动写；写失败保留待写修订，显式重试。历史失败不影响棋谱保存和走棋。当前只单窗口/本机；没有断电与跨进程并发事务保证。

Material3对话框有空态/加载/错误/重试、虚拟列表/200%字号，显式说明未保存内容由草稿管理。纯模型、控制器、文件适配器、UI和装配边界明确，UI不访问文件系统。
