# 测试策略

当前无业务代码，不存在 flutter test 通过记录。文档检查不替代产品测试。

领域：9×10坐标/FEN往返、马腿/象眼/炮架/将帅照面、将军自陷、终局与规则profile；以可授权局面集与手工裁决为基准，避免复制实现自证。棋树测试分支顺序、游标、撤销/重做、注释保存。

UCI：按字节分片/多行/CRLF/长行/未知option/info string/score cp与mate及bound/MultiPV/bestmove无着法；Fake transport 可控延迟重放 stop后迟到消息、连续换局、重启epoch。真引擎测试验证NNUE加载、合法bestmove、stop/quit及线程释放，不断言非确定的唯一最优着法。

存储：事务中断、磁盘满、旧schema迁移/回滚、损坏恢复、草稿与显式保存冲突。导入器对损坏、截断、超限、编码、压缩包路径穿越进行安全测试；所有fixtures自制或记录许可。格式往返比较语义而非二进制一致。

组件/集成：模式互斥、脏数据取消、键盘焦点、屏幕旋转/窗口缩放、200%字号、明暗、读屏语义；完整离线流程为新局→走棋→分支注释→保存→重启恢复→分析→停止。在线测试用本地fake验证无结果/超时/401/429/畸形数据，真实服务仅在授权与配额允许时做冒烟。

CI提案：文档/Skills校验先行；有Flutter工程后 format/analyze/unit/widget，Linux基础CI；各OS runner做桌面构建、Android构建与模拟器、iOS签名前构建。真机性能和热管理、iOS生命周期、五平台安装升级人工验收，不用单个Linux通过冒充全平台。每个失败均记录平台/版本/命令和日志。

性能方法见 PIKAFISH_RESEARCH；阈值需M1测量校准。覆盖率作为缺口信号，不用单一百分比替代风险验收。
