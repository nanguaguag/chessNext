# ADR-083：自建只读棋盘皮肤目录服务端

- 状态：接受（服务端增量 M4-49）
- 日期：2026-11-05
- 范围：F21、B24；不包含登录或用户上传

## 决策

沿用 ADR-074 的自建、只读、可替换目录后端，在原棋子皮肤目录服务中增加可选棋盘皮肤目录根和独立 `/v1/board-catalog` 路由。棋盘目录用 `board-catalog.json` 和 `board-packages/`，与棋子目录的 `catalog.json` 和 `packages/` 隔离。未设置 `SKIN_BOARD_CATALOG_ROOT` 时，新路由不可用，既有棋子接口行为不变。

两目录复用已有ID/文案限制、最多10000项、页大小100、包8MiB上限、许可证/署名元数据和SHA-256绑定。读取拒绝符号链接，并在服务端再次校验包摘要。服务不实现账号、上传、用户点赞或目录写API。目录包使用项目棋盘皮肤schema1；客户端下载后仍需自行做SHA/ZIP/图片验证，并在导入前展示许可并取得用户选择。

## 交付界限

M4-49只交付服务端能力和部署说明。Flutter棋盘目录端口、HTTP实现、离线缓存、目录浏览及确认后导入是后续独立交付；服务端路由存在不能算作在线棋盘皮肤功能完整。发布者需拥有素材再分发权并填写准确许可证与署名。

M4-50沿用同端点输入配置但请求独立`/v1/board-catalog`路径。客户端成功列表页用完整URI做哈希键缓存，最多24页，网络不可达才回退同键缓存并显示缓存时间；服务拒绝/无效schema不回退。下载前列表元数据提供许可证/署名，包通过SHA和board schema校验、名称吻合后再次确认才可导入。用户许可信息随本机board definition和project schema1 ZIP存储；旧包/清单缺少字段时解释为空。M4-50不得用网站皮肤包、图片或元数据填充自建目录。

## 验收

- 无board root时，原 `/v1/catalog` 行为不变，新路径返回404。
- 配置board root时，board清单/包与piece目录隔离；搜索、排序、分页、详情、SHA/Etag包下载均复用同一边界。
- 非GET/HEAD/OPTIONS拒绝；客户端依旧验证包内容。
- 部署通过 `SKIN_BOARD_CATALOG_ROOT` 单独指定目录，不需新端口或账号。
- 服务端schema/路由与Flutter设置弹层通过测试；生产TLS主机、真实board manifest和真实包尚未部署或验收。
