# ADR-057：本机批量导入棋子图片

状态：接受（本机增量）；源站完整导入规格未知  
日期：2026-11-04  
关联：F21、B24、E42、M4-21

## 背景

E42在访客皮肤库导入入口观察到ZIP、图片多选和文件夹三种方式，但没有选择文件或完成导入。因此只有入口为O；成功结果、ZIP结构、目录遍历、冲突覆盖、错误恢复、皮肤包语义均为U。项目已有按PieceSkin与PieceImageSlot保存14类PNG/JPEG覆盖的单图接口和本机仓库。

## 决策

- 单独实现多选图片路径；ZIP和文件夹选择分别作为后续增量，不把同一入口当成三种能力均已支持。
- 每次最多14张，单张仍受512 KiB、PNG/JPEG、1024边长及1MP限制；总字节不超过7 MiB。新增批次上限是本项目资源保护提案P，不声称来自源站。
- 显示全部图像预览并要求映射到14个唯一目标槽；文件名仅在完整匹配槽名/标签时预填建议，用户可改。
- 所有输入先完成解码/尺寸/格式校验，再开始写入；仓库仍按槽位原子替换。批次不伪装成跨槽事务。若中途失败，记录已成功槽位，保留界面并允许重试；重试跳过已成功槽。
- 取消文件选择不改动；取消映射弹窗不写入；本机图像不上传。无新增依赖，复用既有`file_selector`与图片仓库。

## 后果与待验证

多选选择器和预览映射实现本机批次导入，不支持撤销已经成功的各槽替换，也不支持整包回滚。macOS选择器的人工交互尚未验；ZIP、文件夹递归/符号链接拒绝、整套皮肤元数据、覆盖确认、皮肤库搜索/排序/删除/导出和在线自建目录均待后续审计与设计。参考站边界仍按U记录。

## 验收

覆盖批量读取数量/累计大小、单图验证全部先于写入、映射唯一性、偏好/仓库持久化、部分失败与重试跳过已成功槽；再执行根`flutter test`、`flutter analyze`及`flutter run -d macos`。
